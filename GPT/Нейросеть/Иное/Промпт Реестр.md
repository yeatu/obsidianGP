После каждого своего ответа пользователю синхронизируй новые сообщения текущего диалога с реестром текущего проекта.

1. Работай только внутри каталога установленного текущего проекта. Не открывай и не просматривай другие проекты.

2. Найди папку сессии с наибольшим числовым номером в названии «Сессия N». Целевой файл — находящийся в ней «Реестр Сессии.md». Если папка последней сессии или файл реестра отсутствуют, сообщи об этом пользователю и прекрати синхронизацию.

3. Определи границу последней отправки, не читая содержимое реестра:
   - Получи дату и время последнего Git-коммита, изменившего целевой «Реестр Сессии.md».
   - Просмотри только имена файлов в папке «.append-queue» текущего проекта. Не открывай содержимое этих файлов.
   - Если в очереди есть запросы, извлеки временную отметку из имени самого позднего файла.
   - За границу последней отправки прими более позднюю из двух отметок: время последнего коммита реестра и время последнего запроса в очереди. Если очередь пуста, используй время последнего коммита реестра.

4. Выбери все сообщения пользователя и свои ответы в текущем диалоге, появившиеся после этой границы и ещё не отправленные в очередь. Сформируй из них отдельный фрагмент: сохрани полный текст, форматирование, авторство и хронологический порядок. Не включай ранее отправленные сообщения и содержимое существующего реестра.

5. Создай новый файл-запрос с помощью GitHub «create_file» на ветке «main». Путь от корня репозитория:
   `GPT/Нейросеть/Проекты/<Текущий проект>/.append-queue/YYYYMMDDTHHmmssSSSZ-<уникальный-идентификатор>.md`
   Используй UTC-время с миллисекундами и уникальный суффикс. Содержимое файла — только сформированный фрагмент новых сообщений. Не используй «update_file» для реестра, не изменяй и не перезаписывай существующие файлы очереди.

6. После успешного создания файла-запроса заверши свою часть синхронизации. Не выполняй дополнительных действий с реестром: новые сообщения отправлены на сохранение. Не утверждай, что реестр уже обновлён, поскольку создание запроса подтверждает только его отправку.

Если создать файл-запрос не удалось, сообщи об ошибке. Не пытайся записывать сообщения в реестр другим способом и не изменяй другие файлы проекта.
