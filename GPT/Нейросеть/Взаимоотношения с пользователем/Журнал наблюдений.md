# Журнал наблюдений

**Версия структуры:** 0.1  
**Назначение:** хранить значимые наблюдения о предпочтениях пользователя с исходным контекстом и оценкой надёжности.

## 1. Назначение

Журнал содержит наблюдения, извлечённые из рабочих сессий. Он не заменяет исходные реестры сессий и не является самим глобальным профилем.

Исходные реестры сохраняют первичный контекст. В журнал попадают только наблюдения, которые могут иметь значение для адаптации.

Наблюдение не равно окончательному выводу. Изменение профиля производится по правилам из файла «Правила адаптации.md».

## 2. Что фиксировать

Для каждого наблюдения по возможности указываются:

- уникальный ID;
- дата;
- ID и название проекта;
- ID рабочей сессии;
- путь к исходному реестру и указание на фрагмент;
- тип сигнала: прямая обратная связь или косвенная реакция;
- контекст;
- поведение ассистента или обстоятельство, на которое отреагировал пользователь;
- наблюдаемая реакция пользователя;
- предварительная интерпретация;
- возможное альтернативное объяснение;
- предполагаемая область действия;
- уверенность;
- статус проверки.

Не следует переписывать длинные фрагменты переписки, если достаточно точной ссылки на исходный реестр и краткого описания. Короткую цитату можно сохранить, если без неё теряется смысл обратной связи.

## 4. Начальное состояние

Пока в этом журнале нет извлечённых из реестров сессий наблюдений.

Исходные предпочтения, включённые в «Актуальный профиль.md», основаны на прямых пользовательских инструкциях и обратной связи, доступных при создании базовой редакции. Они зафиксированы в самом профиле и его истории изменений.

## 5. Правила ведения

1. Не записывать каждую реплику автоматически.
2. Не трактовать отсутствие реакции как согласие.
3. Не превращать единичный косвенный сигнал в устойчивое предпочтение.
4. Сохранять контекст и альтернативные объяснения.
5. Не удалять опровергнутые наблюдения: менять их статус, сохраняя историю.
6. Не подменять ссылку на исходный реестр пересказом, если первоисточник доступен.
7. Не включать в журнал скрытые рассуждения модели.
8. При исправлении записи сохранять понятную историю изменения.
