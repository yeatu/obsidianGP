# Индекс наблюдений

**Версия структуры:** 0.1  
**Назначение:** обеспечивать выборочный поиск связанных наблюдений по всем проектам без повторного чтения всех реестров сессий.

## 1. Роль индекса

Индекс — вспомогательный поисковый слой, а не первоисточник.

Он хранит короткие сведения для обнаружения подходящих наблюдений и ссылки на исходные записи. Полный контекст остаётся в реестре сессии, а извлечённые наблюдения — в «Журнале наблюдений.md».

Если индекс расходится с исходным реестром или журналом наблюдений, алгоритм должен проверить первоисточник и исправить индекс.

## 2. Поля индексной записи

| Поле | Назначение |
|---|---|
| ID наблюдения | Ссылка на запись в журнале наблюдений |
| Дата | Дата исходной сессии |
| Проект | Проект, в котором возникло наблюдение |
| ID сессии | Идентификатор исходной сессии |
| Категория | Предпочтение или тема наблюдения |
| Область | Глобальная, контекстная, проектная, эпизодическая или неизвестная |
| Краткое содержание | Короткое описание сигнала |
| Уверенность | Оценка надёжности |
| Статус | Текущее состояние наблюдения |
| Источник | Путь к исходному реестру и идентификатору записи |

Индекс не должен копировать полную переписку или длинные цитаты.

## 3. Принцип поиска

При необходимости проверить предпочтение алгоритм:

1. Формулирует категорию или вопрос, по которому нужен поиск.
2. Ищет связанные записи в индексе независимо от проекта.
3. Отбирает подходящие наблюдения с учётом области действия и даты.
4. При необходимости открывает исходные реестры для проверки контекста.
5. Сверяет исходные данные с журналом наблюдений.
6. Фиксирует новые или исправленные сведения в журнале и обновляет индекс.

Поиск по индексу не заменяет проверку первоисточника, когда от него зависит изменение профиля.

## 4. Начальное состояние

Индекс пока пуст: наблюдения из архивов проектов ещё не импортированы и не проиндексированы.

Не следует считать отсутствие записей доказательством отсутствия предпочтений. Оно означает только то, что индексирование ещё не выполнено.

## 5. Правила обновления

- Добавлять запись после появления нового наблюдения в журнале.
- Обновлять статус, если наблюдение подтверждено, опровергнуто или утратило актуальность.
- Не удалять ссылки на исходные реестры после пересмотра вывода.
- Проверять корректность путей и ID.
- Не отмечать запись как проиндексированную до успешного сохранения и контрольного чтения индекса.
