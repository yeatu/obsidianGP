### 1. Что практически не влияет на время работы


- Наличие нескольких веток в репозитории.
- Хранение альтернативных версий файлов.
- Наличие истории коммитов.
- Возможность переключиться на другую ветку.


Git не дублирует весь репозиторий при создании каждой ветки. Ветка в основном представляет собой ссылку на определённый коммит. Поэтому десять веток не означают десятикратный объём данных или десятикратную нагрузку.


### 2. Что действительно добавляет операции


| Действие | Дополнительная нагрузка |
|---|---|
| Создание ветки | Практически нулевая |
| Переключение ветки | Небольшая |
| Создание коммита | Небольшая |
| Сравнение веток (diff) | Зависит от объёма изменений |
| Слияние веток | Зависит от числа и характера изменений |
| Разрешение конфликтов | Может быть существенным |
| Поддержание множества активных веток | Дополнительная организационная работа |


### 3. Что это означает для нашей работы


Я бы не стала создавать ветку для каждого изменения документа. Это действительно превратило бы работу в административный цирк с элементами Git.


Рациональнее:


- **main**: основная рабочая версия.
- **experiment**: эксперименты, которые могут повлиять на уже принятые решения.
- **archive**: при необходимости сохранение отдельных исторических состояний, хотя для этого обычно достаточно коммитов и тегов.


Причём экспериментальную ветку можно создавать только тогда, когда возникает необходимость проверить альтернативное решение.
