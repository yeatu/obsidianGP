# Результат доработки SFRA: Исполнитель 2

**Сессия:** 1  
**Этап дополнения координатора:** 1 из 2  
**Статус этапа 1:** реализован read-only адаптер к SQLite Исполнителя 1 и одноразовый runtime. Промежуточная версия передана аналитику.  
**Этап 2 не завершён:** одноразовый workflow и полный прогон нового runtime на реальном Vault ещё не выполнены.

## 1. Реализовано

- Отдельный пакет `sfra_search` сохраняет функциональность предыдущего прототипа: FTS5 exact/morph channels, русская морфология, Entity Registry, candidate/confirmed/rejected aliases, Mentions, числовая нормализация через `Decimal`, детерминированное ранжирование и API.
- Добавлен `structural.py`: адаптер опубликованной SQLite-схемы Исполнителя 1.
- Добавлен `runtime.py`: одноразовая загрузка структурных узлов, создание FTS5 в памяти, поиск и выдача JSON.
- Добавлены CLI-команды `run-once` и `get-source`.
- Добавлены интеграционные тесты структурной БД и нового CLI.

## 2. Соответствие дополнению координатора

1. Код запускается как обычный Python-процесс; постоянный сервер не создаётся.
2. Входная БД Исполнителя 1 открывается SQLite URI `mode=ro`; включён `PRAGMA query_only=ON`.
3. Читаются только узлы активных документов со статусами `active` / `ambiguous`, без `stale_generation`.
4. `node_id` и `content_hash` берутся из структурного индекса. При их отсутствии выполнение завершается ошибкой; собственные ID не генерируются.
5. Производная FTS5/Entity Registry база создаётся в общей in-memory SQLite и закрывается после поиска.
6. Search hit содержит исходные `node_id` и `content_hash`. `get-source` повторно получает полный узел по обоим полям, не используя исчезнувшую временную FTS-БД.
7. Источник открывается только для чтения; код не изменяет файлы Vault.

## 3. Контракт Исполнителя 1

Адаптер сверен с опубликованной веткой `executor-1/sfra-indexer-session-1`. Используются таблицы `documents` и `structural_nodes`, в том числе поля `source_sha256`, `node_id`, `content_hash`, `raw_text`, `line_start/end`, `char_start/end`, `status` и `stale_generation`.

`content_hash` проверяется по точным UTF-8 байтам `raw_text`. `document_hash` берётся из `documents.source_sha256`; хеш узла не подменяет хеш документа. Если hash полного документа отсутствует, он не выдумывается.

## 5. Ограничения

- В текущей локальной среде не удалось установить `pymorphy3` из PyPI. Все 56 тестов выполнены с резервным NLTK Snowball. Основной путь pymorphy3 должен быть проверен в Actions.
- Новый runtime ещё не запускался на БД полного Vault, созданной самим индексатором Исполнителя 1.
- Одноразовый workflow, публикация артефакта результата и проверка неизменности Vault в рамках нового workflow остаются задачами этапа 2.
- Промышленная готовность и окончательная приёмка не заявляются.
