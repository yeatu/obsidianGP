# Результат доработки SFRA — Исполнитель 2

**Статус:** функциональный автономный прототип опубликован; ожидает независимой проверки аналитика.  
**Область:** только Этап 2 SFRA — локальный поисковый индекс.  
**Реализация:** исходники и тесты в архиве `sfra-search-prototype.tar.xz`, собранном из шести частей в этой папке.

## 1. Что реализовано

- SQLite с миграциями, проверкой FTS5, внешними ключами и проверкой целостности.
- Импорт Node v1 из JSONL через отдельный адаптер.
- SHA-256 точных UTF-8 байтов `raw_text`; строки 1-based inclusive; относительные POSIX-пути.
- История версий с `version_id INTEGER PRIMARY KEY AUTOINCREMENT`, связанный напрямую с FTS5 rowid.
- Обычный поиск ограничен актуальными версиями; историю можно получить по Content Hash.
- FTS5 поиск по исходным словам, фразам, имени документа, пути и заголовкам.
- Отдельный морфологический канал: pymorphy3 как штатный вариант, NLTK Snowball как резервный вариант.
- Точный числовой поиск по Decimal-ключам, группировочным пробелам U+0020/U+00A0/U+202F; числа исключаются из обычного FTS выражения.
- Реестр сущностей и алиасов со статусами candidate/confirmed/rejected; подтверждение/отклонение вручную; неоднозначный алиас возвращает все подходящие Entity ID.
- Карта подтверждённых Mentions без создания отношений между сущностями.
- Детерминированный ranking по уровням, BM25 по возрастанию, стабильный tie-break.
- Идемпотентные транзакционные режимы delta, replace_documents, full_snapshot и явные удаления.
- Программный API и CLI.
- Поисковая выдача имеет bounded excerpt; точный полный источник получается отдельным get_node.

## 3. Искусственные и реальные материалы

**Автоматические тесты:** только искусственные Node v1 JSONL-фикстуры.

**Реальные материалы:** архитектура SFRA и `dump.md` изучены при проектировании; из них взяты реальные контрольные примеры (число 18 518, два независимых документа `Демография.md`, неоднозначные варианты имен). Однако полная индексация реального Vault и интеграция с фактическим экспортом Исполнителя 1 не проводились. Утверждать, что тесты на полном Vault пройдены, нельзя.

## 4. Ограничения

1. PyPI был недоступен из тестовой среды. Поэтому 47 тестов запускались с резервным NLTK Snowball, а не с pymorphy3. Основной pymorphy3 path требует отдельной проверки в окружении с доступом к зависимостям.
2. Реальный JSONL экспорт Исполнителя 1 отсутствует в его опубликованной папке; адаптер проверен на искусственных узлах согласованного Node v1 формата.
3. Новый контракт Executor 3 требует `document_hash` как SHA-256 полного исходного Markdown. Node v1 не содержит это поле. Прототип принимает его как опциональное расширение и возвращает null, если поле не передано. Хеш одного сегмента нельзя выдавать за хеш целого документа. Интеграция требует передачи whole-document hash от Исполнителя 1 или согласования nullable-поля у Executor 3.
4. Промышленная приёмка не заявляется. Прототип передан на аудит.
