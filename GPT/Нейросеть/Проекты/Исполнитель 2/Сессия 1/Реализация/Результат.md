## 1. Изменение контракта статусов

В source/src/sfra_search/structural.py оба проблемных метода теперь допускают только узлы, для которых одновременно выполняются условия:

- документ имеет documents.status = 'active';
- узел имеет structural_nodes.status = 'active';
- stale_generation IS NULL.

Это правило действует и в load_current_nodes(), и в get_source_node(). Значение ambiguous не импортируется в производный FTS5 и не может быть адресно получено как подтверждённый источник.

Проверка наличия node_id и content_hash теперь относится только к допустимым active-узлам. Ambiguous-узел без ID/hash не блокирует импорт, потому что он не должен попадать в индекс. Для active-узлов отсутствие этих полей по-прежнему является ошибкой: E2 не создаёт идентификаторы.

Дополнительно активный дочерний узел не возвращает parent_node_id, если родитель ambiguous или устарел. Сам активный источник остаётся доступным, но неподтверждённый родительский адрес не раскрывается.

E2 не разрешает неоднозначность автоматически. Это ответственность E1. Структурная SQLite E1 открывается в режиме read-only и не изменяется.

## 2. Fixture-тесты

**64 passed, 0 failed, 0 errors, 0 skipped** на Python 3.13 в итоговом workflow.

Искусственные SQLite fixtures проверяют:

| Сценарий | Ожидаемый результат |
|---|---|
| Active-узел с актуальным поколением | Импортируется, ищется и адресно получается |
| Ambiguous-узел | Не импортируется, отсутствует в FTS, get-source его не возвращает |
| Ambiguous без Node ID / Content Hash | Не блокирует загрузку допустимых active-узлов |
| Stale-узел | Не импортируется и не получается |
| Active-узел со stale_generation | Не импортируется и не получается |
| Deleted-узел | Не импортируется и не получается |
| Узел удалённого документа | Не импортируется и не получается |
| Нет active-источника | Поиск возвращает not_found_in_retrieval, список результатов пуст |
| document_hash = null | Остаётся null; не заменяется хешем узла |
| Active-ребёнок с ambiguous-родителем | Источник доступен, parent_node_id = null |
| CLI --package-dir | В скрипте одно объявление аргумента; --help успешно выполняется |

Все перечисленные статусные отрицательные сценарии проверялись на искусственных SQLite fixtures. Они не выдаются за наличие таких записей в текущей production-базе E1.
