### 2.1. Получение структурной базы


Workflow должен:


1. Получать `state/structure.sqlite3` из ветки `sfra-state`.
2. Получать соответствующий `state/manifest.json`.
3. Выполнять проверку соответствия базы манифесту и SHA-256.
4. Отказываться от выполнения при отсутствии базы, повреждении файла или несовпадении контрольной суммы.
5. Использовать исходные Node ID и Content Hash без самостоятельной генерации идентификаторов.


Не создавай новую структурную базу с нуля внутри workflow Исполнителя 2.


### 2.2. Выполнение поиска


Запусти поисковый модуль на реальном Vault из репозитория.


Обязательные условия:


- Python-процесс внутри GitHub Actions;
- использование `pymorphy3` в качестве основного механизма русской морфологии;
- создание поискового FTS5-индекса во временной рабочей директории;
- отсутствие постоянно работающего сервера;
- отсутствие необходимости постоянно сохранять поисковую FTS5-базу.


Не подменяй основной механизм морфологии резервным NLTK Snowball.


### 2.3. Проверка адресации источников


Это одна из главных проверок интеграции.


Поисковый результат должен содержать исходные:


- `node_id`;
- `content_hash`.


Для нескольких найденных результатов выполни адресное получение оригинального источника через предусмотренный интерфейс `get-source` либо его эквивалент.


Проверь:
- что получен именно соответствующий узел;
- что Content Hash совпадает;
- что исходный текст действительно соответствует найденному результату;
- что получение источника работает после построения временного поискового индекса.


Отдельно проверь стабильность Node ID для неизменённых узлов между последовательными состояниями структурной базы.


Учитывай ранее обнаруженное расхождение одинакового Content Hash при разных Node ID в Issue №4.


### 2.4. Проверка неизменности Vault


После выполнения workflow необходимо подтвердить:


- отсутствие изменений файлов исходного Vault;
- отсутствие новых или изменённых файлов внутри каталога `ГП`;
- отсутствие постоянной поисковой FTS5-базы в репозитории;
- отсутствие изменения сохранённой структурной базы со стороны поискового модуля.


Поисковый модуль должен работать с источником в режиме чтения.
