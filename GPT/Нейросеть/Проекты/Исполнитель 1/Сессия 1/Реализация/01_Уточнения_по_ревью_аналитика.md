# Уточнения по замечаниям аналитика — этап B

Все четыре замечания аналитика учтены в модели и тестах этапа B.

## A. Собственное содержимое и диапазон родителя

Для заголовка:

- span / raw_text — заголовок вместе с полным поддеревом до следующего заголовка равного или более высокого уровня;
- content_spans — отдельные диапазоны собственного содержимого: строка заголовка и прямые блоки секции;
- дочерние heading-секции не входят в content_spans родителя.

Для list_item:

- span / raw_text включает вложенные списки;
- content_spans содержит только непосредственные блоки пункта, например его абзац;
- диапазоны вложенных list не входят в content_spans родительского пункта.

content_spans — массив диапазонов, потому что собственное содержимое секции может быть прервано вложенными секциями. Сведение этих диапазонов к одному непрерывному тексту потеряло бы границу владения.

## B. Passage и контекст родителя

Passage.raw_text — исключительно исходный срез источника по Passage.span. Контекст родительских заголовков хранится отдельно:

- context_text — строка с исходными строками заголовков;
- context_spans — координаты этих строк в оригинале.

Контекст не включается в char_start / char_end Passage и не участвует в сравнении raw_text с исходным срезом. Это проверяется тестом большого раздела.

## C. Система координат

Контракт координат:

- line_start / line_end — строки с 1, включительно;
- char_start / char_end — 0-based, полуоткрытый диапазон Python Unicode code points;
- byte_start / byte_end — 0-based, полуоткрытый диапазон UTF-8 байтов;
- raw_text — source[char_start:char_end].

Парсер читает файлы с newline="", чтобы не выполнять преобразование CRLF в LF. Автоматическая валидация сверяет строки, символьный срез и UTF-8 byte offsets. Тесты параметризованы по LF/CRLF и содержат кириллицу, emoji, латиницу с диакритикой, греческие и дополнительные Unicode-символы.

## D. Размер Passage

estimate_words() использует регулярное выражение Unicode word characters и является приблизительной оценкой слов. Это не токенизатор модели. Порог мягкий: группа узлов формируется только по существующим границам дочерних структур. Callout, quote, table и code block остаются атомарными. При отсутствии безопасной границы сохраняется крупный узел с предупреждением.

## E. Контекст Passage для вложенных списков

После замечания аналитика функция _context_for() расширена. Теперь она проходит по цепочке предков:

- каждый heading добавляет собственную строку заголовка;
- каждый list_item добавляет только свои content_spans, то есть непосредственное содержимое пункта без дочерних списков;
- диапазоны сортируются по позиции в первоисточнике и не дублируются.

Так сохраняется исходное условие родительского пункта, например «ученик должен сохранять концентрацию», когда Passage адресует дочерний список этапов испытания. raw_text и координаты Passage не меняются. Новый регрессионный тест прошёл в GitHub Actions.
