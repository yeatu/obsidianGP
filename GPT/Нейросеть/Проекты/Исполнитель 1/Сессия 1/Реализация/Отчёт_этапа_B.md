## 2. Реализованный контракт структуры

Document представлен ParsedDocument и корневым узлом типа document. StructuralNode хранит тип, родителя, heading_path, исходный диапазон, исходный raw_text, дочерние узлы и content_spans. Passage имеет собственный исходный диапазон, отдельное поле контекста и владельца owner_node_key.

Заголовок охватывает собственную секцию вместе с потомками. Его content_spans исключают дочерние heading-секции. У list_item raw_text включает поддерево, а content_spans исключает вложенные списки.

Passage.raw_text всегда является срезом исходного Markdown. Контекст заголовков хранится отдельно в context_text/context_spans и не добавляется в координаты фрагмента.

Node ID и Content Hash пока не генерируются: поля зарезервированы, node_id остаётся NULL. Устойчивое сопоставление и хеширование относятся к этапу C.

## 6. Пример структуры

Вход:

    # Большой раздел

    Абзац 1: важное слово ...

    ## Вложенная тема

    > [!NOTE] Примечание
    > Исходная строка.

Упрощённое дерево:

    Document
    └── heading: Большой раздел
        ├── paragraph: Абзац 1
        └── heading: Вложенная тема
            └── callout: NOTE

Для Passage родительский путь заголовков хранится в context_text/context_spans, а raw_text остаётся точным исходным фрагментом без добавленного заголовка.

## 7. Ограничения этапа B

1. index_vault() выполняет пакетную пересборку, а не инкрементальную синхронизацию.
2. Node ID и Content Hash ещё не назначаются.
3. Контент Callout/blockquote/table/code индексируется как атомарный блок без отдельного поддерева внутренних элементов.
4. Оценка размера — приблизительный подсчёт слов, не число токенов конкретной модели.
5. Markdown парсится в режиме CommonMark с включёнными таблицами. Wikilinks, embeds, properties и сторонние Obsidian-конструкции сохраняются как исходный текст, но не получают отдельной семантической модели.

## 8. Следующий этап

После проверки аналитиком этап C может добавить:

- Node ID и SHA-256 Content Hash;
- хранение версий узлов;
- однозначное сопоставление узлов между переиндексациями;
- статус stale / ambiguous для неоднозначных случаев;
- инкрементальную переиндексацию одного изменённого файла.

FTS5, сущности, фасеты, MCP, эмбеддинги и Context Builder в эту реализацию не добавлялись.
