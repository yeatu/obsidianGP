# E1 — публичный API точного чтения первоисточника

Статус: реализация подготовлена в отдельной PR-ветке; ожидает независимой приёмки аналитиком.

## API

\`\`\`python
get_node_by_id(
    db_path: str | Path,
    node_id: str,
    expected_hash: str,
    vault_root: str | Path,
) -> NodeLookupResult
\`\`\`

\`db_path\` передаётся явно и указывает на существующую SQLite schema v2, восстановленную persistence-механизмом. Скрытой глобальной конфигурации нет. \`vault_root\` — корень конкретного checkout папки \`ГП/\`; путь документа из SQLite разрешается относительно него.

Публичные типы: \`NodeLookupResult\`, \`NodeLookupStatus\` и \`NodeRecord\`. Успешный ответ содержит source-backed \`raw_text\`, \`node_id\`, \`content_hash\`, относительный путь, тип узла, родительский ID, heading path, line/char/byte offsets и проверенный полный SHA-256 исходного документа. Любой неуспешный статус имеет \`node is None\`.

## Проверки перед выдачей

1. Проверяется формат Node ID и expected Hash.
2. Существующая SQLite открывается только с \`mode=ro\` и \`PRAGMA query_only=ON\`; схема должна быть v2.
3. Проверяются integrity/FK, уникальность адресуемой записи, допустимость статусов, безопасная POSIX-форма \`documents.source_path\`.
4. Валидируется вся история \`node_match_events\`, включая allowlist \`event_type\` и JSON payload.
5. Независимо пересчитывается Hash сохранённого \`structural_nodes.raw_text\`; проверяется вся последовательность \`node_versions\` и совпадение текущего снимка с последней версией.
6. Только после DB-only preflight разрешаются \`deleted\` и \`ambiguous\`; исходный Markdown для них не открывается.
7. Для активного однозначного узла путь открывается descriptor-relative с запретом symlink traversal и защитой от выхода из корня; файл проверяется через \`fstat\` до и после чтения, повторно открывается для проверки identity.
8. Проверяется полный SHA-256 и размер файла; строгая UTF-8 декодировка сохраняет исходные LF/CRLF и Unicode.
9. Фрагмент строится только как \`source_text[char_start:char_end]\`; независимо проверяются UTF-8 byte offsets, line coordinates, Content Hash фрагмента и expected Hash.
10. При любом отказе исходный фрагмент, координаты и альтернативный Node ID не возвращаются.

## Статусы

| Статус | Смысл |
|---|---|
| \`ok\` | Текущий активный узел и источник полностью проверены |
| \`stale_source\` | Файл отсутствует/изменился или expected Hash не соответствует текущей версии |
| \`deleted\` | Документ или прежний адрес узла удалён |
| \`ambiguous\` | Старую идентичность нельзя однозначно сопоставить |
| \`not_found\` | Node ID отсутствует |
| \`invalid_request\` | Неверный ID, Hash, путь БД или Vault root |
| \`integrity_error\` | Повреждение БД/истории/координат или небезопасное открытие источника |

## Явная фиксация Vault source

Persistence workflow принимает \`vault_ref\` как явный input. Значение по умолчанию — \`executor-1/sfra-indexer-session-1\`; автоматического переключения на \`main\` нет. Workflow отдельно checkout-ит только \`ГП/\`, определяет фактический \`vault_commit_sha\` командой \`git rev-parse HEAD\` и записывает оба значения в state manifest. Старые \`source_branch\` / \`source_commit\` сохранены как алиасы для совместимости.

## Тесты и защита

\`tests/test_lookup.py\` покрывает:
- успешную выдачу source slice;
- invalid request, not found и неверный expected Hash;
- ambiguous, stale/deleted node и deleted document;
- изменение целевого фрагмента и другой части файла после индексации;
- Unicode, кириллицу, emoji, LF и CRLF;
- повреждённые символьные, байтовые и строковые координаты;
- отсутствие файла, \`../\` и symlink escape;
- повреждённый SQLite raw_text и неизвестное событие сопоставления;
- отсутствие побочных изменений SQLite/Vault;
- отсутствие raw_text в ошибочных ответах.

\`tests/test_state.py\` дополнен проверкой новых manifest-полей и совместимости со старыми \`source_branch/source_commit\` manifest.

## Границы

- SQLite schema v2 сохранена без миграций.
- Принятые B/C parser, identity, storage и indexer не переписывались.
- API не возвращает исторические версии и не подбирает похожие узлы.
- Тесты не используют production \`sfra-state\` и не изменяют исходный Vault.
- Полное принятие зависит от фактических локальных/CI результатов и независимой проверки аналитика.
