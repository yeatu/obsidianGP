## 1. Реализация C1

### SearchAdapter
- Вызывает опубликованный \`sfra_search.runtime.search_structural_database()\`; поиск, FTS, morphology и ranking остаются в E2.
- Producer Node ID + Content Hash сохраняются без подмены.
- E2 tier/BM25 и направление сортировки переносятся без синтетического score.
- Excerpt остаётся только retrieval signal; source raw_text поступает через E1 public reader port.
- Ошибки поиска, пустая выдача, возможная truncation по limit и source rejection отражаются отдельно.

### SourceReader
- Вызовы только через публичные \`sfra_indexer.read_source_scope()\` и \`resolve_current_node()\`.
- Принимаются нативные E1 dataclass results через \`to_dict()\`.
- Проверяются snapshot echo, scope echo, exact target identity, source/document hash, generation, UTF-8 SHA, координаты и пустой fragments при error.
- Проверяются parent ID, единый parent у соседей, source order и уникальность Node ID по ролям.
- Прямого SQL к E1 SQLite и собственного Markdown parsing в E3 нет.

### DependencyResolver и token budget
- Для dependency Node ID выполняется \`resolve_current_node()\`, затем exact node read по текущему Content Hash.
- Fuzzy/historical fallback нет.
- Diagnostics из предыдущего pipeline run очищаются в начале нового run.
- E1 возвращает полный текст; token budget полностью принадлежит E3. При превышении E3 возвращает \`budget_exceeded\` без частичных fragments или откладывает atomic group.
- B1 policy defaults \`normal / () / False\` не описываются как source annotations.

### Snapshot binding
- Vault HEAD == manifest source commit.
- Sidecar checkout должен быть чистым и находиться на ветке \`sfra-state\`.
- SQLite SHA проверен через E1 state verifier и сопоставлен с manifest.
- Manifest SHA вычислен по точным байтам.
- Один SnapshotRef проходит через search, dependency resolution и все scope reads.
