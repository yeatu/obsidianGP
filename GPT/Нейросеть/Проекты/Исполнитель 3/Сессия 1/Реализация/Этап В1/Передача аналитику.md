# Передача аналитику — E3 C1 и gate E3-02

**PR:** [#10 — E3 C1](https://github.com/yeatu/obsidianGP/pull/10), draft, не слит.  
**Ветка:** \`executor-3/context-integration-stage-c1\`.  
**Область C1:** E2 SearchAdapter, native E1 SourceReader adapter, Snapshot binding, E3 DependencyResolver, fixture pipeline.  
**Реальная E1/Vault интеграция:** отдельный SFRA-E3-02 gate; не считается завершённой по fixture-проверкам.

## 1. Реализация

### SearchAdapter
- вызывает опубликованный \`sfra_search.runtime.search_structural_database()\`;
- сохраняет Node ID + Content Hash, E2 tier/BM25 и порядок;
- хранит E2 excerpt только в \`signals.match_excerpt\`;
- получает полный \`raw_text\` только через SourceReader по точному адресу;
- проверяет hash/locator, исключает stale/ambiguous/deleted/not_found;
- не интерпретирует неизвестные E2 match reasons и не подменяет E1 document generation значениями E2.

### E1 SourceReader
Production adapter теперь работает с реальной нативной формой E1 PR #11:
- \`SourceScopeResult.to_dict()\`: \`snapshot_id/scope/status/fragments/anchor/parent/previous/next/document/error\`;
- \`CurrentNodeAddress.to_dict()\`: плоский current address без raw text;
- принимает dataclass results через их публичный \`to_dict()\`;
- передаёт \`snapshot_id\` в оба E1 вызова;
- нормализует все четыре scope без чтения внутренних SQLite таблиц;
- проверяет target hash, source path, whole-document hash, document generation, source SHA, exact UTF-8 content hashes;
- проверяет named relationships, parent ID, common parent и source order соседей;
- отклоняет duplicate Node IDs и partial payload;
- E1 API не получает token budget.

### DependencyResolver
Для каждого dependency Node ID:
1. \`resolve_current_node()\`;
2. берёт текущий Content Hash;
3. \`read_source_scope(scope="node")\` по точному адресу;
4. проверяет snapshot и целостность текста.

Нет fuzzy, historical или similar-node fallback. При ошибке dependency остаётся unresolved; required group остаётся атомарной. Диагностики сбрасываются в начале каждого pipeline run.

### SnapshotRef
E3 binder:
- читает actual Git HEAD Vault и sidecar;
- требует чистые checkout;
- требует локальную ветку sidecar \`sfra-state\`;
- сверяет Vault HEAD с manifest source commit;
- проверяет E1 \`verify_state_directory()\`, SQLite SHA и точный SHA manifest bytes;
- не передаёт Git binding в E1.

### Token budget
E1 всегда возвращает полный текст. E3 считает токены через B1 \`TokenCounterProtocol\`, отказывает/откладывает контекст при превышении бюджета, не обрезает source text.

Policy defaults \`normal / () / False\` применяются только E3 при отсутствии реальных E1 metadata и не выдаются за source facts.

## 2. Проверки C1

- B1 regression suite: 45 tests.
- C1 suite: текущий CI запуск после relationship/diagnostic regressions будет указан в итоговой записи ниже.
- E2 runtime test вызывает опубликованную E2 функцию на временной SQLite fixture.
- Источник raw text в fixture-тестах — fake E1 public API. Это не реальная production E1/Vault интеграция.
- Проверки охватывают четыре scope, wrong hash, stale/ambiguous/deleted/not_found, snapshot mismatch, content/document hash, generation/path, token overrun, atomic required group, sibling relation integrity и repeated pipeline runs.

## 3. Текущий E1 статус и зависимость E3-02

PR #11 в текущей ветке экспортирует:
- \`sfra_indexer.read_source_scope(db_path, vault_root, node_id, expected_hash, *, scope, snapshot_id)\`;
- \`sfra_indexer.resolve_current_node(db_path, node_id, *, snapshot_id)\`;
- публичные result types \`SourceScopeResult\` и \`CurrentNodeAddress\`.

Код включает один SQLite read transaction для одного scope и echo snapshot. E1 CI на текущем PR head успешен.

Однако в главном координационном документе \`PROJECT_TASKS.md\` задача SFRA-E1-01 всё ещё имеет статус \`WAITING_FOR_IMPLEMENTATION\`; E1 analyst checklist и результат не заполнены. Координационный gate разрешает начинать реальную интеграцию после \`ANALYST_COMPLETE_UNREVIEWED\` от E1. Поэтому E3-02 остаётся blocked до фиксации этого статуса; API наличие само по себе не подменяет analyst acceptance.

## 4. Подготовка real integration

Workflow \`.github/workflows/sfra-e3-real-e1-integration.yml\` и runner \`tests/run_real_e1_integration.py\` подготовлены. Они:
- checkout E1 по ref;
- checkout sidecar branch \`sfra-state\`;
- checkout Vault на commit из sidecar manifest;
- создают SnapshotRef через E3 binder;
- выполняют E2 → E3 retrieval → DependencyResolver → E1 resolve/read → все четыре scope → Context Builder → Context Pack;
- проверяют wrong hash и unknown Node ID;
- сравнивают digest SQLite, manifest и tracked Vault files до/после.

До прохождения E1 analyst gate workflow намеренно не объявляется доказательством real integration и не запускается против production sources вне изолированных checkout.

## 5. Итог и следующие статусы

- **C1:** может быть отмечен завершённым после успешного CI на финальном синхронизированном HEAD и проверки analyst checklist.
- **E3-02:** не завершён; ждёт формального E1 analyst completion и затем read-only real integration.
- **Не заявляется:** production integration, until real pipeline log/report proves snapshot identity and source hashes against matching Vault checkout.
