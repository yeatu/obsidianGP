## 1. Что изменено относительно предыдущей проверки

- E1SourceReader now consumes native \`SourceScopeResult\`/\`CurrentNodeAddress\` via \`to_dict()\`, not a synthetic E1 response.
- Parent identity is checked against target.parent_node_id.
- Previous/next siblings must share the target parent and be on the correct side in source order.
- Duplicate Node IDs across roles are rejected.
- Node fragments require parent id, coordinates, source SHA and metadata envelope.
- Resolver diagnostics are reset at the start of each pipeline run; a two-run regression covers stale diagnostic leakage.
- Snapshot binder requires a real local \`sfra-state\` branch checkout, not merely a clean arbitrary Git checkout.
- README and API contract describe the native E1 API and E3-only token budget.
- Real integration artifact records E1/E3 implementation SHAs and the dependency address it resolves.

## 2. CI

On the final synchronized implementation head, the C1 CI must show:
- B1 regression: **45 passed**;

The real integration workflow must pass on the same E3 head and a current E1 public API ref. Both run URLs and the exact E1/E3 SHAs are recorded after the final run completes.

C1 tests include four-scope fixtures, real E2 runtime against temporary structural SQLite, hash/snapshot/generation errors, relation adversarial tests, token budget atomicity, required-group behavior and per-run diagnostic isolation.

## 3. Real E1/E2/E3 integration

The real workflow checks out E1 API, sidecar \`sfra-state\`, and a Vault commit selected from exact manifest bytes into separate GitHub Actions directories. It does not write to production Vault or production \`sfra-state\`.

The machine-readable report records:
- E1 and E3 commit SHA;
- Vault and sidecar commit SHA;
- exact manifest SHA-256 and SQLite SHA-256;
- one snapshot_id passed to all operations;
- E2 hit/candidate counts and top candidate ID/hash/tier/BM25;
- current-node resolution and a real relation-node DependencyResolver resolution;
- node / parent / neighbors / document status, fragment roles, hashes, byte lengths and generation;
- wrong-hash and unknown-node failures;
- Context Pack identity and Included/Deferred counts;
- E3 scope-budget rejection without partial fragments;
- before/after read-only digests and clean checkout assertions.

The Context Pack may legitimately be \`budget_limited\`; the result report must state actual Included/Deferred counts. This is not equivalent to a failed build or to a complete pack.
