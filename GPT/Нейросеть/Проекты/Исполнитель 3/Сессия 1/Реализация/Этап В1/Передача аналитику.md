## 1. Реализация

### SearchAdapter
- Использует опубликованный \`sfra_search.runtime.search_structural_database()\`; поиск/FTS/morphology/ranking остаются в E2.
- Сохраняет producer Node ID, Content Hash, tier/BM25 и direction.
- E2 excerpt является только retrieval signal.
- Оригинальный raw_text приходит только через E1 public API.
- Empty result, search error, possible truncation и source rejection различаются.

### SourceReader / DependencyResolver
- Использует нативные E1 \`SourceScopeResult\` и \`CurrentNodeAddress\` через \`to_dict()\`.
- Поддерживает node / parent / neighbors / document.
- Проверяет snapshot/scope echo, target identity, parent/sibling relation identity, source order, уникальность Node IDs, hashes, path, generation и coordinates.
- Не выполняет SQL в E1 SQLite и не разбирает Markdown.
- DependencyResolver: resolve_current_node → exact current Content Hash → read_source_scope(node).
- Fuzzy/historical fallback отсутствуют; diagnostics изолированы по каждому pipeline run.

### Snapshot и budget
- Vault HEAD == manifest source_commit; sidecar HEAD — чистая ветка sfra-state.
- SQLite SHA и exact raw manifest SHA проверяются E3 binder.
- Один SnapshotRef проходит через поиск, dependencies и все scope calls.
- E1 возвращает полный текст; E3 владеет TokenCounterProtocol и budget. Truncation запрещена.
- B1 defaults normal / () / False отделены от source metadata.

### Real negative matrix

Production-pinned snapshot:
- wrong hash → stale_source / no fragments;
- unknown node → not_found / no address;
- corrupt isolated copy of candidate Markdown → stale_source / no fragments;
- tampered snapshot echo → snapshot_mismatch;
- mismatched request SnapshotRef → snapshot_mismatch before source read;
- tampered document hash → document_hash_mismatch;
- tampered document generation → snapshot_generation_mismatch.

Disposable E1 lifecycle indexes:
- ambiguous immediate sibling after one-to-many remap → ambiguous / no fragments;
- deleted node after public E1 re-index with source file removed → deleted / no fragments.

Важно: ambiguous/deleted lifecycle rows созданы через публичный E1 \`index_vault()\` в отдельном временном sidecar/Vault. Они не утверждаются как состояния production snapshot. E3 runner не исполняет SQL.

Read-only checks:

- both checkout clean.
