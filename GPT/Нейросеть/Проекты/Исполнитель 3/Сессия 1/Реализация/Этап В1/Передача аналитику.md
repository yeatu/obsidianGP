## 1. Состав реализации

### SearchAdapter

Файлы:
- Этап В1/src/sfra_context_integrations/search_adapter.py
- Этап В1/src/sfra_context_integrations/source_protocol.py

Адаптер вызывает реальный sfra_search.runtime.search_structural_database(source_database, query, entities, limit, entity_config). Поиск и ранжирование остаются E2.

Ключевые правила:
- Node ID + Content Hash не изменяются;
- tier/BM25 переносятся без инверсии;
- неизвестные match_reasons не интерпретируются;
- excerpt — только signals.match_excerpt;
- полный raw_text получен только от injected E1 reader и проверен SHA-256 UTF-8;
- E2 index_generation игнорируется для E1 provenance;
- empty retrieval, error, limit truncation, zone post-filter и source rejection отражаются отдельно.

### SourceReader и fixtures

Файлы:
- Этап В1/src/sfra_context_integrations/source_reader.py
- Этап В1/src/sfra_context_integrations/source_protocol.py
- Этап В1/tests/fixtures/source_reader.py
- Этап В1/tests/test_source_reader.py

E1SourceReader проверяет E1 scope response для node / parent / neighbors / document:
- ответ обязан echo-ить тот же snapshot_id;
- requested Node ID + Content Hash обязаны совпасть;
- все fragments должны относиться к одному source_path, document_hash и E1 document-local index_generation;
- content_hash каждого node fragment пересчитывается по точным UTF-8 байтам;
- document fragment пересчитывается по whole-document hash;
- при ошибочном статусе fragments должны быть пустыми;
- scope budget не приводит к усечению текста.

Fixture E1 API использует заранее заданные node records и sibling relationships. В нём нет SQL и Markdown parsing. Это тестовый provider, не production E1 implementation.

### Pipeline

Файлы:
- Этап В1/src/sfra_context_integrations/pipeline.py
- Этап В1/tests/test_pipeline.py

ContextIntegrationPipeline выполняет SearchAdapter → SearchBatch → B1 ContextBuilder → ContextPack → явно запрошенные SourceReader scopes. Один SnapshotRef передаётся в search, B1 dependency resolver и все scope reads.

Fixtures проверяют:
- все четыре scope;
- dependency resolver и atomic required group;
- rejection при другом E1 document generation;
- ContextBuilder token budget без обрезки;
- несовпадающий SnapshotRef;
- отсутствие дальнейших source reads после E2 runtime error.

### Реальный E2 runtime test

Файл: Этап В1/tests/test_real_e2_runtime.py.

Тест устанавливает и импортирует опубликованный E2 пакет, создаёт временную SQLite fixture с E1 structural tables и вызывает реальную функцию search_structural_database() через default SearchAdapter (без injected search callable). Полный исходный текст адаптер получает через E1 fixture. SHA-256 временной SQLite сравнивается до/после.

Это проверяет реальную форму E2 runtime hit, но не реальный Vault и не production E1 Source API.

## 3. Snapshot binding

Файл: Этап В1/src/sfra_context_integrations/snapshot.py.

Mapping:
- vault_commit_sha = pinned Vault checkout HEAD = E1 manifest.source_commit;
- sidecar_commit_sha = pinned sfra-state checkout HEAD;
- manifest_sha256 = SHA-256 точных manifest bytes.

Binder вызывает E1 verify_state_directory, сверяет manifest и database digest. Branch name не разрешается внутри запроса повторно. E1 document generation не сравнивается между разными source_path.

## 6. Что проверить аналитику

1. Соответствие SearchAdapter реальному E2 runtime API и E2 hit contract.
2. Сохранение E2 ranking semantics (tier/BM25), conservative truncation и разделение excerpt/raw_text.
3. Строгость четырёхрежимного SourceReader boundary и фикстур.
4. Snapshot binding и запрет смешивания document generation.
5. Fixture pipeline, dependency atomicity, token budget и error path.
6. Предложение публичного E1 Scope API и текущий запрос в PR #11.

Следующий gate не начинается автоматически. После приёмки C1 ожидается решение E1 по API scope; до этого real SourceReader integration не заявляется.
