- Примеры/search_adapter.batch.json — пример входного SearchBatch с расширенными сигналами.

Все записи с префиксом fixture_ и путями fixtures/ являются искусственными тестовыми примерами, а не содержимым Vault. Числа токенов в примере Context Pack иллюстративные; рабочие значения будут вычисляться TokenCounter.

## Вопросы для проверки

1. Приемлема ли граница budget_tokens: лимит для Included + provenance, а размер полного JSON-ответа измеряется отдельно как response_tokens_estimated?
2. Достаточно ли атомарности узлов и необязательных preservation/required_with для недопущения потери критических правил и зависимостей?
3. Подтверждается ли предложенное соглашение SHA-256 по точным UTF-8-байтам узлового среза или требуется иной hash scope?
4. Допустимы ли дополнительные секции Known и Version Changes?
5. Подходит ли MCP Python SDK 2.3.0 как целевая ветка для окружения координатора?
6. Подходит ли tiktoken 0.14.0 с начальной кодировкой o200k_base при явном указании, что точность относится к кодировке, а не к неизвестной модели клиента?
7. Достаточно ли описаны точки согласования интерфейсов с Исполнителями 1 и 2?

## Ограничения, вынесенные на согласование

- Контекстный Builder не может самостоятельно распознавать критичность правил по смыслу без выхода за границы задания.
- Покрытие без явного focus может быть пустым; искусственная декомпозиция задачи не выполняется.
- Неизвестный/устаревший Node ID не заменяется похожим материалом.
- Схема Node ID, координат и Content Hash должна быть окончательно согласована с индексатором.
- Жёсткий лимит на весь JSON одновременно с обязательной передачей всех Deferred потребует пагинации Deferred; это не включено в текущий MVP-контракт.

## Контрольные инварианты

- raw_text не обрезается, не пересказывается и не очищается.
- разные source_path сохраняются раздельно.
- одинаковый текст в разных структурных местах не считается доказанным дублем.
- not_found_in_retrieval не означает отсутствия данных в Vault.
- known действует только для пары Node ID + Content Hash и только в рамках конкретного запроса.
- MCP-сервер не хранит состояние диалога.
- read_source проверяет ожидаемый хеш до чтения и не делает fuzzy fallback.

**Просьба к аналитику:** проверить проектные решения и вернуть блокирующие/неблокирующие замечания. До получения проверки реализация Этапа Б не начинается.
