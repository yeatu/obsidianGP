# Передача аналитику — SFRA-E3-V2.2

**Issue:** #15  
**Роль реализации:** Исполнитель 3  
**Независимая проверка:** Аналитик 3  
**Область:** только non-production Issue validation и safe worker core.

## Реализованный scope

- Strict parser для Issue record, exact repository/title/author checks, fail-closed allowlist и 32 KiB UTF-8 body cap.
- Принимается ровно один JSON envelope или один fenced json block; duplicate keys, extra text, malformed JSON и non-finite constants отклоняются.
- Envelope schema sfra.issue.v1, UUID v4, search_vault/read_source operations и strict payload schemas с additionalProperties=false, включая вложенные focus/known objects.
- SHA-256 вычисляется по точным исходным body bytes. In-memory status store фиксирует первый hash; изменённое тело получает permanent invalid-request outcome и не доходит до application service.
- Typed transport status schema v2 с обязательными status_schema_version, request_body_sha256 и worker_commit_sha; business status отделён от transport status.
- SafeResultProjector выдаёт только allowlisted status/scope/counts/diagnostic codes.
- IssueWorkerCore использует injected IssueReaderPort, TransportStatusStorePort и V2.1 application services; получает один pinned SnapshotRef на вызов и проверяет его после service call.
- Fake/in-memory tests, no external API/client/workflow/write implementation.

## Adversarial tests

Проверяются чистый JSON и один fenced block, extra text, multiple blocks, malformed JSON, duplicate keys, invalid UTF-8, body over 32 KiB, wrong event/repository/title/author, empty allowlist, invalid protocol/UUID/operation, missing/extra envelope and payload fields, nested extra fields, incorrect hashes/scopes/budgets, status-v2 type/extra-field rejection, source-content leakage through malicious fixtures, application-service non-invocation for rejected requests, changed-body hash rejection, pinned SnapshotRef identity and exception-message sanitization.

## Security boundaries

No GitHub SDK/API, secrets, network or write calls; no real Issue/comment reads or writes; no Issues-opened, schedule or workflow-call event handler; no Vault text/path/title/hash serialization; no retries, leases, concurrency, recovery, MCP, HTTP/webhooks or deployment. Public source content remains DENY BY DEFAULT.
