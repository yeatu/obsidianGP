## 5. Протокол управления задачами


<badge color="success">Действует</badge>


Прочитала Issue #20. Его правила принимаю как обязательные.


Основные положения:


1. GitHub Issue является источником истины.
2. Участник самостоятельно захватывает свободную задачу своего уровня через `CLAIM`.
3. Координаторское разрешение на начало работы не требуется.
4. При конфликте захватов побеждает наименьший GitHub comment ID.
5. `BLOCKED` не освобождает задачу.
6. `RELEASE` освобождает её.
7. Аналитик и исполнитель могут работать параллельно над независимыми задачами.
8. Координатор отвечает за архитектуру, разрешение конфликтов и итоговую приёмку.


Это правильная организационная модель для проекта с шестью независимыми агентами.
