## Но есть важный нюанс: кто именно будет ждать?


Здесь нужно различать два ожидания.


**1. GitHub Actions будет ждать ваш компьютер.**


Например, пользователь создал Issue, но компьютер выключен. Задача останется в очереди. Когда компьютер включится, Runner подключится к GitHub и сможет принять её.


**2. ChatGPT Web не будет автоматически ждать завершения задания в открытом диалоге.**


Он создаст Issue, GitHub Actions запустит задачу, локальный обработчик выполнит её и оставит результат в Issue. Но GitHub не отправляет в текущий диалог ChatGPT автоматический сигнал, который гарантированно возобновит остановившийся ответ.


Для ChatGPT это будет двухэтапная операция:


- отправить запрос и получить идентификатор Issue;
- проверить этот Issue позднее, прочитать готовый результат и продолжить обработку.


Можно организовать проверку результата отдельным действием в том же диалоге, но гарантировать автоматическое ожидание и возобновление без специального механизма интеграции нельзя.


## Что важно предусмотреть по безопасности


Runner получает возможность выполнять задания на вашем компьютере.
 Поэтому нельзя просто разрешить ему запускать любые команды, написанные в Issue.

## Что это означает для архитектуры SFRA


Получается интересное разделение ответственности:


| Компонент | Назначение |
|---|---|
| ChatGPT Web | Формирует запрос, читает результат, анализирует его |
| GitHub Issues | Очередь запросов и хранилище ответов |
| GitHub Actions | Оркестрация, проверка и контроль выполнения |
| Self-hosted Runner | Мост между облачной задачей и вашим компьютером |
| SFRA Worker | Управляет выполнением операции |
| Local MCP | Предоставляет локальному Worker доступ к данным и инструментам |
| Локальное хранилище | Реальные данные на вашем компьютере |


**Ключевой момент:** Local MCP в этой схеме не подключается к ChatGPT Web. Его вызывает локальный SFRA Worker, запущенный через Self-hosted Runner. Это принципиально иная роль: локальный интерфейс доступа к данным, а не транспорт ChatGPT.


Таким образом, вы можете сохранить уже разработанные MCP-компоненты и использовать их как локальный исполнительный слой, не делая их обязательной частью интерфейса ChatGPT Web.


**Мой вывод:** эту архитектуру стоит рассмотреть как отдельный вариант Web-адаптера с локальным исполнением. При этом первоначальную synthetic-only фазу из координаторского решения #75 нужно сохранить: сначала проверить весь цикл на синтетических данных, не подключая реальный Vault.
