# Матрица сценариев SFRA v1

| Сценарий | Фикстура или документ Vault | Что должно быть проверено |
|---|---|---|
| Заголовки H1–H6 | headings_and_duplicates.md | уровни 1–6, корректные границы |
| Повторяющиеся заголовки | headings_and_duplicates.md | два одинаковых заголовка остаются разными узлами |
| Вложенные списки, 4 уровня | nested_lists.md | цепочка родителей, глубина, диапазоны |
| Списки без пустых строк | nested_lists.md | пункты не склеиваются и не теряются |
| Длинный пункт | nested_lists.md | конец длинного фрагмента не обрезан |
| Родительский пункт и дочернее ограничение | nested_lists.md | у потомка сохранён родительский контекст |
| Markdown-таблица | block_structures.md | таблица и строки не разрываются произвольно |
| Цитаты | block_structures.md | границы цитируемого блока |
| Obsidian Callout | block_structures.md и Перси Уизли.md | callout отделяется от обычной цитаты |
| Блок кода | code_links_unicode.md | fenced-блок не интерпретируется как Markdown-структура внутри |
| Markdown-ссылка с URL | code_links_unicode.md и Преподаватели.md | URL и текст ссылки сохранены |
| Кириллица | все фикстуры и Vault | смещения символов и UTF-8-байтов согласованы |
| Неразрывный пробел | whitespace.md и Демография.md | U+00A0 не превращается в обычный пробел |
| Несколько пустых строк | whitespace.md и Преподаватели.md | пустые строки не поглощают соседние блоки |
| CRLF и emoji | crlf_unicode.md | окончания строк не нормализуются, byte/char offsets не смешиваются |
| Пустой файл | empty.md | отсутствие фиктивных содержательных узлов |
| Документ без заголовков | no_headings_mixed.md, Рэддл.md | текст и списки индексируются без требования H1 |
| Смешанная структура | no_headings_mixed.md | соседние блоки разных типов не сливаются |
| Ограничение сканирования | весь Vault | ни один путь вне ГП/ не попал в результат |

## Реальные документы Vault

1. `ГП/фракции/Рэддл.md` — документ без Markdown-заголовков, с глубоко вложенными списками и табами.
2. `ГП/персонажи/ученики/Иное/Перси Уизли.md` — Obsidian Callout и многострочная цитата.
3. `ГП/персонажи/ученики/Молодая кровь/Генрих Фауст.md` — длинный документ, заголовки H1–H3, цитаты и списки.
4. `ГП/принципы написания/принципы.md` — короткая иерархия списков без заголовков.
5. `ГП/иное/Демография.md` — краткий текстовый файл без заголовков.
6. `ГП/разобрать/Демография.md` — таблицы, заголовки, неразрывные пробелы и длинные абзацы.
7. `ГП/персонажи/преподаватели/Преподаватели.md` — множество Markdown-ссылок, U+00A0 и большие интервалы пустых строк.

Оба файла `Демография.md` существуют в разных каталогах и должны сохраняться как два разных документа. Текстовый дамп использовался только как вспомогательный источник: тесты ориентируются на файлы текущего дерева Git.

## Критические случаи для аудита индексатора

- Заголовок внутри fenced code block не должен создавать узел заголовка.
- Callout — цитата со специальным маркером; нельзя потерять маркер `[!NOTE]` или смешать его с телом соседней цитаты.
- Повторяющиеся заголовки не должны приводить к коллизии идентификаторов или слиянию разделов.
- Вложенность списков определяется уровнем отступа и структурой Markdown, а не только наличием пустых строк.
- Табуляция и пробелы могут смешиваться; нельзя считать один таб равным одному пробелу без установленного правила.
- Соседние пункты без пустых строк должны оставаться разными пунктами.
- Все содержательные символы должны присутствовать в исходных фрагментах узлов; пустые разделительные строки могут не иметь собственного узла.
- Markdown-таблица требует корректного распознавания строки-разделителя и строк с ячейками; вертикальная черта внутри экранированной ячейки — отдельный риск.
- Кириллица и U+00A0 требуют согласованных единиц координат. Байтовый диапазон нельзя сравнивать с индексом Python-строки.
- CRLF и LF должны обрабатываться без незаметной нормализации, если координаты и хеш должны ссылаться на исходные байты.
- Для emoji и составных символов длина в UTF-8 байтах, Python code points и UTF-16 code units различается.
- Пустой файл, файл из одних переводов строк и файл без заголовков — валидные входы.
- Родительский узел должен сохранять контекст, необходимый для понимания дочернего ограничения.
- Последний символ файла без завершающего перевода строки не должен теряться.
- Соседние документы с одинаковым именем должны различаться полным относительным путём.
- Сканер не должен подниматься выше `ГП/`, индексировать фикстуры, дамп или служебные файлы репозитория.

## Учет исследовательского прототипа

В основной ветке уже есть `research/markdown-parser/prototype.py` и исследовательская документация. Прототип использует `markdown-it-py`, строит spans через исходные строки и возвращает char/UTF-8 byte offsets. У него пока нет трёх публичных функций SFRA (`scan_vault`, `parse_document`, `export_index`), поэтому данный стенд не подменяет эти функции вызовами прототипа. При появлении v1 адаптер должен отобразить реальную схему результата на NodeView, сохранив line/char/byte координаты.
