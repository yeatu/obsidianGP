# SFRA Markdown Indexer (v1)

Первая версия структурного индексатора Markdown для Obsidian. Обходит только выбранный каталог `ГП/`; соседние каталоги репозитория не сканируются.

## Требования

- Python 3.10+
- Только стандартная библиотека Python; сторонних зависимостей нет.

## Запуск из корня репозитория

    python -m tools.sfra_indexer --root "ГП" --output "sfra_index.json"

JSON создаётся в корне репозитория, вне `ГП/`. Экспорт внутрь индексируемого каталога запрещён API.

## API

    from tools.sfra_indexer import scan_vault, parse_document, build_index, export_index
    paths = scan_vault("ГП")
    document = parse_document(paths[0], "ГП")
    result = build_index("ГП")
    export_index(result, "sfra_index.json")

build_index() добавлен поверх запрошенного API: он индексирует все найденные файлы, сохраняет диагностику ошибок отдельных документов и продолжает работу с остальными.

## Структурная модель

- document — корневой узел файла.
- heading_h1 ... heading_h6 — разделы; текст узла простирается до следующего заголовка того же или более высокого уровня.
- list и list_item — списки; вложенный пункт является дочерним узлом ближайшего родительского пункта.
- paragraph, blockquote, callout, table, table_row, table_cell, code_block, thematic_break — прочие блочные элементы.
- Каждый узел хранит точный source_text, отдельный SHA-256 и координаты.
- Строки нумеруются с 1, end_line включительный. Смещения start_* и end_* нулевые, конец диапазона не включается.
- start_char/end_char измеряются в Unicode code points Python; start_byte/end_byte — абсолютные смещения в байтах UTF-8.
- ID строятся из SHA-256 относительного пути и порядкового номера узла, не из текста. ID стабилен при редактировании текста без изменения порядка/числа структурных узлов; вставка узла выше по документу может изменить последующие порядковые ID.

## Ограничения v1

- Это детерминированный rule-based разбор, а не полный CommonMark AST; редкие граничные конструкции могут классифицироваться как абзацы.
- Вложенные цитаты сохраняются внутри одного узла цитаты. Callout — отдельный узел без внутреннего разбиения тела на абзацы.
- Таблицы поддерживают экранированный символ вертикальной черты, но сложные нестандартные конструкции не нормализуются.
- Вложенные списки учитывают пробелы и табуляцию (табуляция раскрывается в 4 колонки); многоабзацный элемент списка остаётся одним list_item.
- Indented code blocks без fenced-разметки отдельно пока не выделяются.
- Узел раздела хранит весь текст раздела, включая вложенные разделы; это может увеличить размер JSON.
- YAML frontmatter, Obsidian-ссылки/embed и inline HTML не выделяются в отдельные типы узлов.
