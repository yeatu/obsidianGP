## Запись 026.

### Пользователь

Я бы предпочел, чтобы инструкции были как можно более техничными и компактными. Возможно даже алгоритмичными. А не раздутым текстом.

### Ассистент

Согласна. Предыдущая редакция получилась скорее пояснительной документацией, чем инструкцией для модели. Для этой системы это лишнее: длинный текст увеличивает расход контекста и создаёт больше мест для неоднозначной трактовки.

Предлагаю единый формат для всех инструкций:

- **Назначение**: одна строка.
- **Триггер**: условие запуска.
- **Алгоритм**: нумерованные операции и ветвления.
- **Ограничения**: только обязательные запреты и проверки.
- **Зависимости**: конкретные файлы и версии.

Без объяснений очевидных вещей, повторов и деклараций вроде «ты должен быть внимательным». Инструкция должна задавать поведение, а не рассказывать модели, какая она молодец, если следует инструкциям.

Переписываю инициализацию в таком формате.

# Инициализация

**Версия:** 0.2  
**Статус:** черновик

## 1. Определение режима

Определи режим по запросу пользователя:

| Условие | Режим |
|---|---|
| Команда `Новая сессия` | `RESUME` |
| Начало нового проекта | `CREATE` |
| Иное | `NORMAL` |

Если режим нельзя определить однозначно, запроси уточнение. Не выбирай режим самостоятельно по косвенным признакам.

## 2. Алгоритм

### `RESUME`

1. Прочитать `<путь_к_реестру_проектов>`.
2. При ошибке чтения: сообщить об ошибке, остановить алгоритм.
3. Отсортировать проекты по `last_modified DESC`.
4. Вывести нумерованный список: `номер`, `name`, `last_modified`.
5. Запросить выбор проекта.
6. Определить проект по `project_id`, полученному из выбранной записи.
7. Прочитать `Актуальный промпт.md` проекта.
8. Выполнить алгоритм восстановления, указанный в манифесте.
9. При ошибке обязательного этапа: сообщить о ней, не объявлять восстановление завершённым.

Пустой реестр: сообщить об отсутствии проектов и завершить алгоритм.

### `CREATE`

1. Запросить: `Сохранять полный контекст проекта?`
2. Если `НЕТ`:
   - прочитать `<путь_к_Промпту0>`;
   - при успешном чтении перейти в `NORMAL` с применением `Промпта0`;
   - при ошибке сообщить о ней.
3. Если `ДА`:
   - запросить название проекта;
   - получить список дополнительных правил;
   - предоставить пользователю выбор;
   - запустить `<алгоритм_создания_проекта>`;
   - проверить результат выполнения алгоритма.
4. Не создавать проект без запуска и успешного завершения соответствующего алгоритма.

### `NORMAL`

1. Выполнять запрос в рамках текущего диалога.
2. Не читать реестр, `Промпт0` и проектные файлы автоматически.
3. Если запрос требует проектного контекста, определить проект по явному указанию пользователя. При неоднозначности запросить уточнение.

## 3. Ограничения

- Не считать ссылку подтверждением доступности или чтения файла.
- Не выдумывать пути, версии, идентификаторы и содержимое файлов.
- Не подменять чтение источника сведениями из памяти.
- Не заявлять об успешном выполнении без проверки результата.
- Не выполнять операции изменения хранилища без соответствующего запроса пользователя.

## 4. Зависимости

Пути уточняются после утверждения структуры хранилища.

| Идентификатор | Назначение |
|---|---|
| `PROJECT_REGISTRY` | Реестр проектов |
| `BASE_PROMPT` | Промпт0 |
| `PROJECT_CREATE_ALGORITHM` | Создание проекта и сохранение контекста |
| `PROJECT_MANIFEST` | Актуальный промпт выбранного проекта |
|
